## 2. เตรียมเครื่อง (ทำครั้งเดียว)
สถานะเครื่องคุณ (เช็คเมื่อ 21 ต.ค.):

| สิ่งที่ต้องมี | สถานะ |
|---|---|
| Git | ✅ 2.56 |
| Node.js | ✅ 24 |
| GitHub CLI (`gh`) | ❌ ยังไม่ได้ติดตั้ง |

**ขั้นที่ 1:** เปิด Terminal ในแอป (Ctrl+`) แล้วติดตั้ง GitHub CLI
```bash
winget install --id GitHub.cli -e
```

**ขั้นที่ 2:** ปิดแอป Claude แล้วเปิดใหม่ เพื่อให้ระบบเห็นคำสั่ง `gh`

**ขั้นที่ 3:** ล็อกอิน
```bash
gh auth login --hostname github.com --git-protocol https --web --scopes workflow,user
```
หน้าจอจะขึ้นรหัส 8 ตัว ให้กด Enter เบราว์เซอร์จะเปิดขึ้นมา จากนั้นใส่รหัสนั้นแล้วกดยืนยัน

**ขั้นที่ 4:** ตรวจว่าล็อกอินสำเร็จ
```bash
gh auth status
```
ต้องเห็น scope ครบ 3 ตัว คือ `repo`, `workflow`, `user` ถ้าขาดตัวไหน ให้รัน `gh auth refresh -h github.com -s workflow,user`

> **ทำไมต้องมี `workflow` และ `user`**
> - `workflow`: ใช้ push ไฟล์ GitHub Actions (ระบบอัปเดตสถิติและเกม) ถ้าไม่มี scope นี้ GitHub จะปฏิเสธการ push
> - `user`: ให้ AI แก้ bio และลิงก์ในหน้าโปรไฟล์ได้ แต่จะแก้ก็ต่อเมื่อคุณอนุมัติแล้วเท่านั้น
>
> ถ้ายังไม่มีบัญชี GitHub ให้สมัครที่ github.com ก่อน AI สมัครแทนไม่ได้

**ขั้นที่ 5 (ไม่บังคับ):** จัดการ Connectors
- `.claude/settings.json` ปิด connectors ที่ต่อผ่านบัญชี claude.ai (เช่น Vercel, Supabase) ไว้แล้ว เพื่อประหยัด token มีผลเฉพาะในโฟลเดอร์นี้
- Blender และ Unity ถ้าไม่ได้ใช้ในงานนี้ ปิดได้ที่ Settings › Connectors

## 3. กรอก profile.yaml
**หลักการ**
- กรอกเฉพาะข้อมูลจริง
- ช่องที่เว้นว่าง (`""` หรือ `[]`) จะไม่แสดงบนโปรไฟล์
- AI ถูกห้ามไม่ให้แต่งข้อมูลขึ้นเอง

| ช่อง | ใส่อะไร | ตัวอย่าง | ถ้าเว้นว่าง |
|---|---|---|---|
| `identity.github_username` | ชื่อบัญชี GitHub **(ต้องมี)** | `kittikarn-dev` | AI จะถามก่อน publish |
| `identity.full_name` | ชื่อเต็ม | | แสดงแค่ Kittikarn |
| `identity.location` | ที่อยู่ | `Bangkok, Thailand` | ไม่แสดง |
| `identity.role_line` | ตอนนี้ทำอะไรอยู่ | `CS student @ …` | ไม่แสดง |
| `identity.tagline` | ประโยคเด่น 1 บรรทัด | | AI ร่างมาให้เลือก 3 แบบ |
| `identity.bio` | แนะนำตัว 1–3 ประโยค | | ไม่แสดงย่อหน้านี้ |
| `identity.open_to` | เปิดรับงานแบบไหน | `[freelance, collab]` | ไม่แสดง |
| `skills[].summary` | สรุปสายนั้นไม่เกิน 40 ตัวอักษร | `Fast, beautiful web apps` | การ์ดแสดงแค่ชื่อกับไอคอน |
| `skills[].stack` | เครื่องมือที่ใช้จริง | `["TypeScript", "React"]` | การ์ดไม่มีชิปบอก stack |
| `skills[].since` | เริ่มทำสายนี้ปีไหน | `"2022"` | ไม่แสดง |
| `skills[].link` | ลิงก์ผลงานของสายนั้น | | กดการ์ดแล้วไปที่เว็บหลุมดำ |
| `projects` | ผลงานเด่น (ดูตัวอย่างในไฟล์) | | AI เลือก repo ที่ได้ดาวมากที่สุดให้ |
| `links.*` | ช่องทางติดต่อที่เปิดเผยได้ | `https://www.linkedin.com/in/...` | ไม่มีปุ่มนั้น |
| `avatar.mode` | `keep` (รูปเดิม) หรือ `monogram` (AI ออกแบบโลโก้ K ให้) | | ใช้รูปเดิม |

**เคล็ดลับ**
- ใส่ stack เฉพาะที่ใช้จริง เครื่องคุณต่อ Unity, Blender, Supabase และ Vercel ไว้ ใส่ได้ถ้าคุณใช้มันจริง
- Section B (`settings`) คือค่าที่คุณเลือกไปแล้ว ไม่ต้องแก้ ถ้าอยากเปลี่ยนให้บอก AI
- กฎ YAML: ข้อความต้องอยู่ใน `"..."` รายการเขียนแบบ `["a", "b"]` และต้องย่อหน้าด้วยเว้นวรรค ห้ามใช้ Tab

## 4. เริ่มงานกับ Claude Code (ทำทุก session)
1. เปิดแอป Claude ไปที่แท็บ **Code** แล้วเลือกโฟลเดอร์ `Githubprofile`
2. เช็คแถวใต้ช่องพิมพ์ให้ครบ 3 อย่าง:
   - **Mode = Plan**: ตั้งเป็นค่าเริ่มต้นไว้แล้ว แต่แอปจะจำ mode ล่าสุดที่ใช้ในโฟลเดอร์นี้ ถ้าเปิดมาแล้วไม่ใช่ Plan ให้เลือก Plan เอง
   - **Model = Opus 5.5** (Ctrl+Shift+I): ตั้งไว้ใน settings แล้ว
   - **Effort** (Ctrl+Shift+E): เลือกตามตารางในข้อ 7
3. พิมพ์ `/kickoff` เพื่อให้ AI เลือกเฟสถัดไปเอง หรือพิมพ์ `/kickoff P2` เพื่อระบุเฟส
   - ถ้าไม่อยากใช้คำสั่ง `/` ให้เปิด `prompts/03-claude-code-kickoff.md` แล้วคัดลอกส่วนที่อยู่ใต้เส้น `---` ไปวางแทน
4. AI จะอ่านเฉพาะไฟล์ที่จำเป็น แล้วส่ง**แผน**มาให้ดู ระหว่างนี้มันจะยังไม่แก้ไฟล์ใดๆ จนกว่าคุณจะอนุมัติ
5. ตอบแผน:
   - `ok` หรือ `เอาเลย` = อนุมัติ
   - `แก้ข้อ 3 เป็น …` = ขอแก้เฉพาะจุด
   - `ทำไมเลือกแบบนี้` = ถามเหตุผล
6. หลังอนุมัติ เลือก mode ที่จะให้ทำงาน:
   - **Accept edits**: AI แก้ไฟล์ได้เลย ทำงานเร็ว
   - **Manual**: AI ถามคุณก่อนทุกครั้ง
7. AI ลงมือทำ ตรวจคุณภาพเอง แล้วส่ง screenshot พร้อมคะแนนมาให้ดู
8. ถ้าพอใจ พิมพ์ `/ship` แล้ว AI จะอัปขึ้น GitHub ตอน push แอปจะถามยืนยันอีกชั้นหนึ่ง
9. จบเฟสแล้ว**ให้เริ่ม session ใหม่**สำหรับเฟสถัดไป ROADMAP บันทึกสถานะไว้แล้ว AI จึงทำต่อได้ทันที

## 5. ระบบอนุมัติ 3 ชั้น
| ชั้น | กลไก | ผลที่ได้ |
|---|---|---|
| 1 | Plan mode + กฎข้อ 1 ใน CLAUDE.md | AI ต้องเสนอแผนก่อนเสมอ ไม่ว่าจะอยู่ mode ไหน |
| 2 | Permission rules ใน `.claude/settings.json` | git push, gh api, การสร้าง repo, การติดตั้ง package จะเด้งถามคุณทุกครั้ง |
| 3 | `/ship` | ทุกการ publish เกิดเมื่อคุณพิมพ์คำสั่งนี้เองเท่านั้น AI เรียกเองไม่ได้ |

- force push
- ลบ repo
- แสดง token (`gh auth token`)
- `rm -rf`
- อ่านไฟล์ `.env`
- โหมด Bypass permissions

## 6. Skills, Rules และ Hook
| คำสั่ง / skill | ใครเรียก | ทำอะไร |
|---|---|---|
| `/kickoff [เฟส]` | คุณ | เริ่ม session: เลือกเฟส อ่านเฉพาะที่จำเป็น แล้วส่งแผน |
| `/ship [profile\|site\|sidebar]` | คุณ | ตรวจก่อนปล่อย แล้ว commit, push และเช็คของจริงบน GitHub |
| `space-svg` | AI (คุณพิมพ์ `/space-svg` เองก็ได้) | สูตร 12 แบบสำหรับทำ SVG เคลื่อนไหวที่แสดงบน GitHub ได้จริง เช่น หลุมดำ การ์ด ดาวโคจร |
| `readme-rules` | AI | สิ่งที่ GitHub แสดงหรือตัดทิ้ง และ layout ที่ใช้ได้จริง |
| `visual-qa` | AI (หรือคุณพิมพ์ `/visual-qa`) | ตรวจด้วยตาทั้ง desktop/mobile และ dark/light, เช็ค animation, ให้คะแนน 10 หมวด |
| `github-ops` | AI | คำสั่ง gh ที่ถูกต้องสำหรับทุกขั้น เช่น สร้าง repo, เปิด Pages, แก้ bio, เพิ่มลิงก์ social |

- **Rules** (`.claude/rules/`): กฎสั้นๆ ที่โหลดเองเฉพาะตอน AI แตะไฟล์ประเภทนั้น เช่น พอแตะไฟล์ `.svg` ก็จะโหลดกฎ SVG ตอนที่ไม่ได้ใช้จึงไม่กิน token
- **Hook**: ทุกครั้งที่ AI เขียนหรือแก้ไฟล์ `.svg` หรือ `README.md` ตัว `tools/check.mjs` จะตรวจทันที ถ้าเจอปัญหา AI จะเห็น error และต้องแก้ให้ผ่าน ปัญหาที่จับได้ เช่น
  - มี script
  - ลิงก์ฟอนต์จากภายนอก
  - รูปที่ไม่มี alt
  - มีคำว่า TODO หลงอยู่
  - ไฟล์ใหญ่เกินงบ
- อยากตรวจเองเมื่อไหร่ก็ได้: `npm run check` (ก่อนปล่อยจริงใช้ `npm run check -- --publish`)

## 7. Effort: ใช้ high, xhigh หรือ max ตอนไหน
โปรเจกต์นี้ตั้งค่าเริ่มต้นเป็น **high** ไว้ใน settings แล้ว (ปกติ Opus 5.5 เริ่มที่ medium)

| เฟส | งาน | Effort ที่แนะนำ |
|---|---|---|
| P0 | ตั้งค่า + ดูโปรไฟล์ตัวอย่าง | high |
| P1 | hero หลุมดำ + การ์ด 5 ใบ | xhigh (เปลี่ยนเป็น max ถ้ารอบแรกได้ไม่ถึง 9/10) |
| P2 | สถิติ + contribution galaxy | high (ช่วงทำ galaxy ใช้ xhigh) |
| P3 | เกม Feed the Black Hole | high |
| P4 | เว็บ WebGL | xhigh (ช่วงทำ shader ใช้ max) |
| P5 | sidebar + ขัดเกลางาน | high (รีวิวรอบสุดท้ายใช้ max) |

- **วิธีเปลี่ยน effort**: กด Ctrl+Shift+E ในแอปเดสก์ท็อป หรือพิมพ์ `/effort xhigh` ใน CLI
- **ใช้ max เท่าที่จำเป็น**: max คิดลึกที่สุดแต่ใช้ token มาก และเอกสารทางการเตือนว่าอาจ "คิดเกิน" จนได้ผลไม่คุ้ม จึงควรใช้กับงานที่ยากจริงเท่านั้น
- **คิดลึกเฉพาะข้อความเดียว**: ใส่คำว่า `ultrathink` ลงในข้อความนั้น
- **AI จะเตือนเอง**: ในแผนจะบอกว่าเฟสนั้นควรใช้ effort ระดับไหน ถ้าที่ตั้งอยู่ต่ำกว่า มันจะขอให้คุณปรับก่อนเริ่มงาน

| P3 | เกม Feed the Black Hole | ลองเล่นจริง 1 ครั้งด้วยการเปิด issue, `/ship` |
| P4 | เว็บ `<username>.github.io` หลุมดำ 3D | อนุมัติการสร้าง repo ตัวที่ 2, ลองเล่นเว็บ, `/ship site` |
| P5 | เสนอ bio, ลิงก์ และ status, ออกแบบ avatar monogram (ถ้าเลือกไว้) | อนุมัติค่า, อัปโหลด avatar เอง, ปักหมุด repo เอง, `/ship sidebar` |

## 9. ประหยัด token 10 ข้อ
1. **1 เฟส = 1 session** จบเฟสแล้วเปิด session ใหม่ ROADMAP จำสถานะไว้ให้แล้ว
2. เริ่มงานด้วย `/kickoff` ทุกครั้ง ไม่ต้องอธิบายงานใหม่
3. ใช้ effort ตามตาราง อย่าเปิด max ทิ้งไว้
4. อย่าสลับ model กลาง session เพราะ cache จะเริ่มใหม่ ข้อความถัดไปจะแพงขึ้น
5. อย่าวาง log ยาวหรือรูปจำนวนมาก บอกสั้นๆ ว่าเห็นอะไร หรือแปะเฉพาะส่วนที่สำคัญ
6. ตอบแผนแบบเจาะจง เช่น "แก้ข้อ 3" ดีกว่าเขียนสั่งใหม่ทั้งหมด
7. ปล่อยให้ hook และ validator จับ error แทนการให้ AI ไล่ตรวจเอง
8. ปิด connector ที่ไม่ใช้ (โปรเจกต์นี้ปิด connectors ของ claude.ai ไว้แล้ว)
9. ถ้าบทสนทนายาวมาก ให้พิมพ์ `/compact` (ถ้ามีในเมนู `/`) หรือเริ่ม session ใหม่
10. ดูว่า skill แต่ละตัวกิน context เท่าไหร่ด้วย `/skill-doctor` และตรวจไฟล์คำสั่ง AI ทั้งหมดด้วย `/doctor prompt-audit`

## 10. แก้ปัญหาที่เจอบ่อย
| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| ติดตั้งแล้วแต่ขึ้น `gh: command not found` | PATH ยังไม่อัปเดต ให้ปิดแล้วเปิดแอป Claude ใหม่ |
| push ไม่ผ่าน ขึ้นว่า "…without `workflow` scope" | รัน `gh auth refresh -h github.com -s workflow` |
| push ไม่ผ่าน ขึ้น GH007 (private email) | git email ต้องเป็นแบบ noreply ซึ่ง P0 ตั้งให้แล้ว ถ้ายังเจอให้บอก AI |
| รูปบนโปรไฟล์ไม่เปลี่ยนหลัง push | GitHub cache ไฟล์ไว้ไม่กี่นาที รอสักครู่แล้วรีเฟรชด้วย Ctrl+F5 |
| animation ไม่ขยับ | ลองเช็คว่าปิด Animation effects ของ Windows ไว้หรือเปล่า (Settings › Accessibility › Visual effects) ถ้าปิดอยู่ ระบบจะขอ reduced motion และโปรไฟล์จะแสดงแบบภาพนิ่ง ซึ่งเป็นพฤติกรรมที่ออกแบบไว้ |
| สถิติไม่อัปเดต | ดูที่แท็บ Actions ของ repo: GitHub ปิด workflow อัตโนมัติถ้า repo ไม่มีความเคลื่อนไหว 60 วัน ให้กด Enable |
| เว็บ `.github.io` ขึ้น 404 | เช็คว่า Settings › Pages › Source เป็น GitHub Actions และครั้งแรกต้องรอสักครู่ |
| AI ลงมือแก้โดยไม่ส่งแผนก่อน | เลือก Plan ใน mode selector แล้วพิมพ์ "ส่งแผนก่อน" (กฎข้อ 1 บังคับไว้อยู่แล้ว) |
| ขึ้นข้อความ "hook error" | รัน `npm run check` เพื่อดูรายละเอียด ถ้าตัว hook เองมีปัญหา ลบส่วน `hooks` ใน `.claude/settings.json` ออกชั่วคราว |
| แจ้งเตือน issue เยอะ (จากเกม) | ที่หน้า repo กด Watch › Custom แล้วปิด Issues |

## 11. Prompt ทั้ง 3 ไฟล์ และสิ่งที่ v2 ปรับจาก v1
| ไฟล์ | ใช้กับ | ใช้เมื่อไหร่ |
|---|---|---|
| `01-ultimate-prompt-v1.md` | AI ทั่วไป | เก็บไว้เทียบกับรอบ 2 |
| `02-ultimate-prompt-v2.md` | Claude.ai, ChatGPT, Gemini ฯลฯ | อยากให้ AI ตัวอื่นช่วยทำหรือช่วยคิด วางทั้งไฟล์ได้เลย |
| `03-claude-code-kickoff.md` | Claude Code ในโฟลเดอร์นี้ | ทุก session (หรือพิมพ์ `/kickoff` แทน) |

**จุดอ่อนของรอบ 1 และสิ่งที่รอบ 2 แก้**

| # | จุดอ่อนของ v1 | v2 แก้อย่างไร |
|---|---|---|
| 1 | ขอให้ "interactive" แต่ไม่บอกข้อจำกัดของ GitHub AI จึงอาจใช้ JS, CSS หรือ hover ที่ GitHub ตัดทิ้ง | เพิ่ม `<platform_truths>` 6 ข้อ และกำหนด interactive 3 ชั้นที่ทำได้จริง |
| 2 | "สวยที่สุด" หรือ "ว้าว" วัดผลไม่ได้ | ใช้ rubric 10 หมวด ทุกหมวดต้องได้ ≥ 8 และเฉลี่ย ≥ 9 |
| 3 | สั่งว่า "ห้ามมั่ว" แต่ไม่มีกลไกบังคับ | ข้อมูลต้องมาจาก profile.yaml หรือ API เท่านั้น ช่องว่างแปลว่าไม่แสดง และ validator จับ placeholder ได้ |
| 4 | ขอทุกอย่างในคำตอบเดียว คุณภาพจึงตก | แบ่งเป็น 6 เฟส แต่ละเฟส: แผน → อนุมัติ → ทำ → ตรวจ → ปล่อย |
| 5 | ไม่มีขั้นตรวจงาน | preview ผ่าน Markdown API ของ GitHub, เช็ค desktop/mobile, dark/light, reduced motion และงบขนาดไฟล์ |
| 6 | สั่งให้อัปขึ้น GitHub แต่ไม่มีด่านอนุมัติหรือเรื่องสิทธิ์ | มี approval gates, ระบุ scope ที่ต้องใช้ และใช้อีเมล noreply |
| 7 | ไม่พูดถึงฟอนต์ใน SVG (ฟอนต์จากภายนอกโหลดไม่ได้) | แปลงตัวอักษรเป็น path หรือฝัง subset ของฟอนต์ลงในไฟล์ |
| 8 | ไม่มีชิ้นงาน signature หน้าตาจึงซ้ำกับ galaxy banner ที่มีคนทำแล้ว | contribution galaxy ที่หลุมดำกินกราฟจริง + เกม + เว็บ 3D |
| 9 | กำหนดสีไว้แค่โหมดมืด | เพิ่มสีสำหรับโหมดสว่าง ทุกสีผ่าน contrast ระดับ AA |
| 10 | ไม่พูดเรื่อง license | ฟอนต์ OFL, simple-icons CC0, ห้ามคัดลอกโค้ด GPL หรือ Shadertoy |
| 11 | ไม่มีงบประสิทธิภาพ | กำหนดงบ KB ต่อไฟล์, จำนวน animation และห้าม animate filter |
| 12 | ให้เทไฟล์ทั้งหมดออกมาโดยไม่มีโครงสร้าง | มี output contract (แยกกรณีที่ AI ใช้ tools ได้กับใช้ไม่ได้) และ self-check ก่อนส่ง |

**แล้ว 03 ต่างจาก v2 อย่างไร:** 03 สั้นมาก เพราะความรู้ทั้งหมดถูกแยกไปไว้ใน CLAUDE.md, SPEC, ROADMAP, skills และ rules ซึ่ง Claude Code โหลดเฉพาะตอนที่ต้องใช้ จึงได้คุณภาพระดับเดียวกับ v2 แต่ใช้ token ต่อ session น้อยกว่ามาก

## 12. คำถามที่พบบ่อย
- **เปลี่ยนธีมสีทีหลังได้ไหม** ได้ บอก AI ว่าจะเปลี่ยนเป็น Nebula Neon หรือ Aurora Quasar แล้ว AI จะเสนอแผนแก้ `design/tokens.json` จากนั้น build ใหม่ทั้งหมด เพราะทุกไฟล์ดึงสีจาก tokens
- **อยากเพิ่ม skill ที่ 6** เพิ่มใน `profile.yaml` แล้วบอก AI การจัดการ์ดจะเปลี่ยนจาก 3+2 เป็น 3+3
- **ไม่อยากให้ไฟล์ AI เป็น public แล้ว** เปลี่ยนเป็น `ai_files_public: false` แล้วบอก AI ให้ย้ายไฟล์เหล่านั้นเข้า .gitignore ส่วนไฟล์ที่เคย push ไปแล้วจะยังอยู่ในประวัติ git
- **ใช้ ChatGPT หรือ Gemini แทนได้ไหม** ใช้ `prompts/02` ได้ แต่ระบบอัตโนมัติ (skills, rules, hook, `/kickoff`, `/ship`) ใช้ได้เฉพาะใน Claude Code
- **เกมจะโดนสแปมไหม** มีการจำกัดไว้ 1 ครั้งต่อคนต่อชั่วโมง และรวมไม่เกิน 30 ครั้งต่อชั่วโมง ถ้าอยากปิดเกม ให้บอก AI ปิด workflow `feed.yml`
- **ข้อมูลส่วนตัวจะรั่วไหม**
  - commit ใช้อีเมล noreply ไม่ใช่อีเมลจริงของคุณ
  - `/ship` สแกนหา token ก่อน push ทุกครั้ง
  - ปุ่ม email จะมีก็ต่อเมื่อคุณใส่อีเมลไว้ใน profile.yaml
- **อยากย้อนการเปลี่ยนแปลง** บอก AI ว่า "ย้อน commit ล่าสุด" มันจะใช้ `git revert` ซึ่งไม่ลบประวัติ
